# *Design Thinking*

> O intuito do DT é ser aplicado de forma coletiva e colaborativa para reunir pontos de vista distintos

> *Design thinking* is an **iterative** process in which you seek to understand your users, challenge assumptions, redefine problems and create innovative solutions which you can prototype and test.

# Princípios

- Soluções alcançadas pela coletividade
- Utiliza a "empatia"
- Não funciona linearmente, mas sim de forma mais orgânica, progressiva
- Pode ser adaptado a diferentes áreas
- Funciona melhor quando não há clareza do problema ou da solução

# Por que DT?

- Baixo custo de aplicação
- Permite contemplar cenários e visões distintas
- Valoriza todos os participantes

# Variantes
Cinco etapas

1. **Empatize** com os usuários (ou clientes, estudantes, etc)
2. **Defina** necessidades para os usuários
3. **Ideação**; busque soluções coletivamente
4. **Proposição** de uma solução
5. **Teste** uma solução entregando ao usuário

# Definição do Problema

```mermaid
flowchart LR
    Análise --> Síntese
    Síntese --> Análise
```

:: left ::

**Análise**

> Dividir o problema em menores partes, conceitos. Compreender as interações entre as partes. Extrair conclusões.

:: right ::

**Síntese**

> Simplificar processos. Destacar o que é mais significativo. Reconectar as partes de um todo.

---
layout: quote
---

# Definição de Problema

> Descrição de usuário + Necessidades + Proposta

# Fases
Ideação

- O que é possível fazer a partir do que foi visto?
- Quais as ideias que surgiram?
- *Brainstorming* sem julgamentos
    - "Não existem ideias ruins"
- Post It
- Criar um conjunto de possibilidades e não necessariamente a ideia "certa"
- Deve resultar em 4 ideias

---

# Fases
4 ideias

- A mais racional
- A mais provável de agradar ao grupo
- A preferida do grupo
- A mais rentável ou a mais arriscada

---

# Ideação
Como fazer?

- *Brainstorming*
- *Brainwriting*
- *Mindmap*
- *Storyboard*

---

# Fases
Prototipagem

- Criar protótipos antes do produto final
- Aprimoramento antes da produção final

---

# Fases
Testes

- Disponibilizar o produto ao usuário
- Observar as reações
- Monitorar a *performance*
- Colocar o produto criado nas mãos do usuário

# Defina o Problema
